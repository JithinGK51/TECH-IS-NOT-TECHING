# Contributing to DAKSHA CARNIVAL - Typing Challenge Game

Thank you for your interest in contributing to the DAKSHA CARNIVAL typing challenge game! This document provides guidelines and information for contributors.

## 🤝 How to Contribute

### 1. Fork the Repository
- Click the "Fork" button on the GitHub repository page
- Clone your forked repository to your local machine

### 2. Create a Feature Branch
```bash
git checkout -b feature/your-feature-name
```

### 3. Make Your Changes
- Follow the coding standards outlined below
- Test your changes thoroughly
- Update documentation if needed

### 4. Commit Your Changes
```bash
git commit -m "Add: Brief description of your changes"
```

### 5. Push to Your Fork
```bash
git push origin feature/your-feature-name
```

### 6. Create a Pull Request
- Go to the original repository on GitHub
- Click "New Pull Request"
- Select your feature branch
- Provide a detailed description of your changes

## 📋 Coding Standards

### Python Style Guide
- Follow [PEP 8](https://www.python.org/dev/peps/pep-0008/) style guidelines
- Use meaningful variable and function names
- Add docstrings for functions and classes
- Keep lines under 100 characters when possible

### Code Structure
```python
def function_name(parameter):
    """
    Brief description of what the function does.
    
    Args:
        parameter: Description of the parameter
        
    Returns:
        Description of what is returned
    """
    # Implementation here
    pass
```

### Comments
- Use `#` for single-line comments
- Use `"""` for multi-line comments and docstrings
- Explain complex logic and algorithms
- Keep comments up-to-date with code changes

## 🧪 Testing

### Before Submitting
- Test your changes on different Python versions (3.7+)
- Verify the game runs without errors
- Check that all features work as expected
- Test on different operating systems if possible

### Test Cases
- Game startup and initialization
- Mouse click functionality
- Timer accuracy
- Leaderboard functionality
- Screen transitions
- Error handling

## 📝 Pull Request Guidelines

### PR Title
Use a clear, descriptive title:
- `Add: New feature description`
- `Fix: Bug description`
- `Update: Component description`
- `Remove: Unused code`

### PR Description
Include:
- Summary of changes
- Motivation for the changes
- Testing performed
- Screenshots (if applicable)
- Breaking changes (if any)

### Example PR Description
```markdown
## Summary
Added voice announcements for minute milestones in the game timer.

## Changes
- Implemented text-to-speech functionality
- Added minute announcement system
- Enhanced timer with professional female voice

## Testing
- Tested on Windows 10/11
- Verified voice announcements work correctly
- Confirmed no impact on game performance

## Screenshots
[Include screenshots if applicable]
```

## 🚫 What Not to Contribute

- Code that breaks existing functionality
- Changes that don't follow the project's coding standards
- Features that are too complex for the scope of the project
- Code without proper testing

## 🏷️ Issue Labels

When creating issues, use appropriate labels:
- `bug`: Something isn't working
- `enhancement`: New feature or request
- `documentation`: Improvements to documentation
- `good first issue`: Good for newcomers
- `help wanted`: Extra attention is needed

## 📞 Getting Help

### Questions and Discussions
- Use GitHub Issues for bug reports and feature requests
- Use GitHub Discussions for general questions
- Check existing issues before creating new ones

### Development Setup
1. Clone the repository
2. Ensure Python 3.7+ is installed
3. Run the game to verify setup
4. Make your changes
5. Test thoroughly
